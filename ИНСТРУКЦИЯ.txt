Force Mail From — инструкция
==============================

Зачем это нужно
---------------
На Hosting Ukraine (ukraine.com.ua, панель adm.tools) исходящее письмо
блокируется, если заголовок From — чужой домен. Частый случай:

  WordPress / WooCommerce / форма / Wordfence шлёт письмо от
  ваш@gmail.com  или  wordpress@сайт.com,
  а хостинг ждёт ящик, который реально создан на аккаунте.

Хостинг тогда пишет: «Некорректный заголовок From» / Invalid From
и присылает уведомление владельцу аккаунта.

Плагин заставляет WordPress всегда отправлять от ящика домена сайта.
Gmail посетителя, если он был в форме, уходит в Reply-To — ему можно ответить.

Кому подходит
-------------
- WordPress на Hosting Ukraine (и похожих хостингах с тем же правилом From).
- Не нужен, если почта уже уходит через внешний SMTP (WP Mail SMTP + Gmail
  SMTP, SendPulse и т.п.) — там другая схема, этот файл может помешать.
- Не WordPress (OpenCart, самописный PHP) — этот файл не поможет.

Что скачать
-----------
Два файла из этой папки:

  force-mail-from.php   — сам плагин
  ИНСТРУКЦИЯ.txt        — этот текст

Что поменять в force-mail-from.php
----------------------------------
Обычно достаточно ОДНОЙ строки.

1) Префикс ящика (обязательно, если у вас не admin@)

   Найдите:

     define( 'FORCE_MAIL_USER', 'admin' );

   Подставьте локальную часть своего ящика:

     admin   →  admin@ваш-сайт.com
     info    →  info@ваш-сайт.com
     noreply →  noreply@ваш-сайт.com

   Домен подставится сам из настроек WordPress. Файл один и тот же
   на всех сайтах: для site-a.com получится admin@site-a.com,
   для site-b.com — admin@site-b.com.

2) Карта исключений (только если ящик НЕ равен префикс@домен-сайта)

   Раскомментируйте блок FORCE_MAIL_MAP в файле и впишите пары:

     'домен-сайта-без-www' => 'полный@ящик',

   Примеры:

     'shop.com'        => 'sales@shop.com'
     'blog.shop.com'   => 'admin@shop.com'
     'old.com'         => 'admin@main.com'
       (у old.com нет своего ящика — письма пойдут с ящика main.com)

   Если карта пустая — используется только FORCE_MAIL_USER@домен.

Что сделать в панели хостинга (без этого плагин бесполезен)
-----------------------------------------------------------
Плагин не создаёт почтовый ящик и не включает отправку в панели.

1. Почта → Почтовые ящики → создать ящик на домене сайта
   (тот же адрес, который получится в пункте выше).

2. Хостинг → Мои сайты → нужный сайт → Настройки сайта
   → поле «Исходящая почта» → выбрать этот ящик → Сохранить.

3. Если сайтов несколько — шаги 1–2 для каждого сайта.
   Ящик и «Исходящая почта» должны быть на ТОМ ЖЕ домене,
   что и From в плагине. Иначе хостинг снова заблокирует письмо.

4. По желанию: Настройки хостинг-аккаунта → исходящая почта
   по умолчанию — любой существующий ящик аккаунта.
   Это подстраховка для cron и mail() без -f.

Куда положить файл
------------------
На каждом WordPress:

  /wp-content/mu-plugins/force-mail-from.php

Папки mu-plugins может не быть — создайте её.
Права как у соседних файлов WordPress (обычно 644).

Активировать плагин в «Плагины» не нужно: mu-plugins грузятся сами.

Как проверить
-------------
1. В WordPress отправьте тестовое письмо
   (форма, «забыли пароль», плагин безопасности — что удобнее).
2. В письме отправитель должен быть ваш@домен-сайта, не Gmail.
3. На следующий день не должно прийти уведомление хостинга
   про некорректный From.

Типичные ошибки
---------------
- В From Gmail/Mail.ru, а ящик на хостинге не создан.
- «Исходящая почта» в настройках сайта пустая — тогда PHP часто
  шлёт от служебного ящика вида логин@hosting-XX.default-host.net,
  и From с доменом сайта снова не совпадает.
- В карте оставили чужие домены (скопировали файл у знакомого
  и не очистили FORCE_MAIL_MAP).
- Файл лежит в wp-content/plugins/ — так он не включится сам.
  Нужна папка mu-plugins.
- Поставили плагин, но в WooCommerce / CF7 всё ещё прописан Gmail.
  Плагин это перебьёт, но лучше сразу поменять From в настройках
  магазина и форм на ящик домена.
